# One country, multiple portraits: representativeness in GPS-based mobility data is source-specific and spatially dependent

This repository contains the data, code, model outputs, and supporting documentation for the paper: "One country, multiple portraits: representativeness in GPS-based mobility data is source-specific and spatially dependent"

The repository allows inspection of the municipal-level data inputs, rerunning the main computational workflows and tracing the outputs used to assemble the paper figures and tables.

## Repository structure

```text
data/
  raw/                         Municipal-level input data and spatial files
  processed/                   Model-ready inputs for the explain-bias workflows
code/
  01_measure_bias/             Workflow to estimate representativeness bias
  02_explain_bias/             Model fitting, validation and population/households sensitivity
  style/                       Shared plotting styles
results/
  measure_bias/                Outputs from the bias measurement stage
  explain_bias/                Model outputs, predictions, SHAP values, maps, and diagnostics
manuscript/
  figures/
    code/                      Python plotting and spatial sensitivity notebooks
    data/                      Plotting inputs and sensitivity summaries
    plots/                     Source plot panels
    visualisations/            Assembled figure assets
  supplementary-figures/       Supplementary figures and editable table artifacts
  tables/                      Manually assembled table artifacts
docs/
  data-availability.md         Data and code availability statement
  figure-reproducibility.md    Figure-to-notebook mapping and panel settings
  workflow.md                  Measurement, modelling and plotting workflow
  methods/                     Method notes and hyperparameter documentation
  project_notes/               Historical project notes retained for transparency
  variable_dictionary/         Variable documentation
```


## Data

The raw data included here are aggregated at the municipality level. They include:

- census-derived municipal population data;
- aggregated active-population counts from Facebook mobility data;
- aggregated active-device counts from phone/GPS-based mobility data;
- spatial boundary files used for municipal and state-level analyses.

Prepared modelling inputs also include demographic, socioeconomic and digital-access covariates. Here, `raw` refers to inputs to the municipal analysis, not individual mobility records.

See [data-availability.md](docs/data-availability.md) for the data and code availability statement.

## Reproducibility Workflow

See the [figure reproducibility guide](docs/figure-reproducibility.md) for the notebooks, settings and outputs associated with each manuscript figure and supplementary item. The [workflow overview](docs/workflow.md) explains upstream processing and model fitting.

To regenerate plot panels from saved results, start with the Python notebooks in [manuscript/figures/code](manuscript/figures/code). Set the working directory to that folder and follow the figure guide for dataset selection, selective cell execution and export settings. Refitting models is not necessary for this route.

The upstream measurement and modelling workflows are written in R/Quarto:

1. Run [code/01_measure_bias/measure_bias_full.qmd](code/01_measure_bias/measure_bias_full.qmd) to compute representativeness bias from raw municipal population and active-population inputs.
2. Use the processed explain-bias inputs in [data/processed/explain_bias](data/processed/explain_bias) for the modelling workflows.
3. Run the explain-bias workflows in [code/02_explain_bias](code/02_explain_bias):
   - `explain_bias_holdout_gridsearch_pvalue.qmd`
   - `explain_bias_blocked_cv_gridsearch.qmd`
   - `explain_bias_blocked_cv_randomsearch.qmd`
4. Inspect model outputs under [results/explain_bias](results/explain_bias).
5. Generate source panels with the Python notebooks and assemble figures and tables under [manuscript](manuscript).

The QMD input and output settings must be selected for each run; a single execution does not generate every dataset/specification combination. See the workflow guide for working directories and result naming.

The final paper figures and tables were assembled manually from outputs generated by the scripts. The underlying computational outputs and supporting plot/table assets are included.

## Software requirements

Measurement and modelling use R and Quarto. Main R dependencies include:

- `tidyverse`, `dplyr`, `readr`
- `sf`, `spdep`, `spgwr`
- `ggplot2`, `viridis`, `patchwork`
- `xgboost`, `caret`, `yardstick`, `Metrics`
- `SHAPforxgboost`, `shapviz`, `pdp`
- `foreach`, `doParallel`, `parallel`
- `rsample`, `spatialsample`, `vtreat`

Plotting uses Python and Jupyter notebooks, with packages including NumPy, pandas, Matplotlib, SciPy, GeoPandas, jenkspy, mapclassify, libpysal, esda, splot and seaborn. Several notebooks also import statsmodels and prophet. Consult each notebook's import cells for its dependencies.

The QMDs contain package-installation helpers, but software versions are not pinned in a shared environment lockfile.
